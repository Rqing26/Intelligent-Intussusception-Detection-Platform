# 算法分工与适配层说明

> 面向：**检测模块（队友A）**、**分类模块（队友B）**
> 维护：平台方
> 目标：两个人**各写各的目录、各自迭代、互不干扰**，同时对平台只暴露**一个入口**。

---

## 一、整体分工与数据流

```
医生上传影像
      │
      ▼
平台（我负责）：上传/存储/传路径/落库/展示/报告/审计
      │  调用唯一入口 detect_intussusception(image_path)
      ▼
┌─────────────────────── 适配层 pipeline.py（我写，薄，基本不动）───────────────────────┐
│   load_image(path)  读图（含 DICOM 解析）                                              │
│        ↓                                                                             │
│   detection.detect(image)        ← 队友A：检测（定位病灶 → ROI）                       │
│        ↓  ROI                                                                        │
│   classification.classify(roi)   ← 队友B：分类（三分类 + 置信度）                       │
│        ↓  ClassificationOutcome                                                      │
│   组装成平台契约 DetectionResult 并做合法性校验                                         │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

**核心原则：内部分得越开越好，对外只留一个入口。**

**入口优先级（适配层自动判断，按顺序取第一个可用的）**：

| 优先级 | 入口 | 启用条件 |
|:--:|------|------|
| 1 | A/B 真实流水线 | `detection.READY` 与 `classification.READY` 都为 True |
| 2 | **队友融合模型 `team_model`** | 依赖已安装 + `algorithm/weights/` 下 12 个权重齐全 |
| 3 | Mock 占位 | 以上都不满足（保证平台随时能跑通） |

> 目前生效的是第 2 条：`backend/algorithm/team_model.py`（YOLO 切面 + 横纵切 5 折集成 + ResNet18），
> 详见 `docs/融合模型接入说明.md`。等 A/B 两个模块都实现好并把 `READY` 改成 `True`，会自动切回第 1 条。

## 二、目录归属（谁改哪个目录）

```
backend/algorithm/
├── interface.py          ← 平台契约（DetectionResult）  ⛔ 不要改（已冻结）
├── contracts.py          ← A 与 B 之间的数据契约          ⛔ 不要改（要改先商量）
├── pipeline.py           ← 适配层（我维护，各方代码唯一交汇点）
├── team_model.py         ← 已交付的融合模型（切面YOLO + 横纵切5折集成 + ResNet18）
├── weights/              ← 该融合模型的 12 个权重文件（约 150MB，不进 Git）
├── selftest.py           ← 自测脚本（你们可直接用）
├── detection/            ← 队友A 独占，随便改（只要 detect 签名不变）
│   ├── __init__.py       → 提供 detect(image) -> ROI|None   【READY 开关在这里】
│   ├── model.py          ← 你的模型代码
│   └── weights/          ← 你的权重文件
└── classification/       ← 队友B 独占，随便改（只要 classify 签名不变）
    ├── __init__.py       → 提供 classify(roi) -> ClassificationOutcome 【READY 开关在这里】
    ├── model.py
    └── weights/
```

> **两个人只动自己的目录 → 永远不会改到同一个文件 → 不会打架。**
> `team_model.py` 与 `weights/` 属于已交付资产，改动前先跟平台方确认。

## 三、队友A：检测模块契约

```python
def detect(image) -> ROI | None
```

| 项 | 说明 |
|----|------|
| 输入 `image` | 已加载的图像（`numpy.ndarray`，RGB 或灰度）。由适配层 `load_image()` 统一读入，**含 DICOM 解析** |
| 返回 | `algorithm.contracts.ROI` 对象 |
| 未检出病灶 | 返回 `None`（适配层按"全图送分类"处理），或返回 `ROI(image=原图)`，两种都支持 |

`ROI` 字段：
```python
ROI(
    image           = 裁剪后的病灶图,      # 必填（不方便裁剪就放原图）
    box             = (x1, y1, x2, y2),  # 可选，原图坐标；前端会在原图上叠加显示病灶框
    score           = 0.93,              # 可选，检测置信度；会显示在「检测模型」那一行
    annotated_image = 带病灶框的标注图,    # 可选，平台存盘后结果页出现「原图 / AI 标注图」切换
)
```

`annotated_image`（**带病灶框的标注图**）支持三种形态，任选其一：

| 形态 | 写法 | 依赖 |
|------|------|------|
| `bytes` / `bytearray` | `annotated_image=buf.tobytes()`（cv2.imencode / PIL 写进 BytesIO 后的字节） | 无（**推荐**） |
| `str` / `Path` | `annotated_image="vis.jpg"`，你自己写好的文件 | 无（平台会复制到 `uploads/results/`，你不用管生命周期） |
| `numpy.ndarray` | `annotated_image=vis`（H×W 或 H×W×3） | 需要 pillow |

> 平台会把它存到 `uploads/results/`，结果页可切换「AI 标注图」、打印报告优先用它；
> 同时给了标注图和 `box` 时，前端**以标注图为准**，不再叠加坐标框（避免同一个框画两次）。
> 图存不下来（格式不对 / 体积超 20MB）**不影响诊断结果入库**，只会少一张标注图（日志有告警）。
> 重新检测或删除影像时，旧标注图会被自动清理。

### 三.1 顺带声明你的模型名（前端会显示）

在同一个 `__init__.py` 里加两行常量，平台就会在结果页把你的模型名单独展示出来：

```python
NAME = "YOLOv8n-Intussusception"   # ⚠️ 改成你的真实模型名
VERSION = "1.0.0"                  # ⚠️ 改成你的版本号
```

- 前端结果页显示两行：`检测 <A的NAME> v<VERSION>` 与 `分类 <B的NAME> v<VERSION>`；患者详情页时间线、打印报告同样区分展示。
- 平台还会自动记录 A/B 各自的**耗时**（`detection_ms` / `classification_ms`）。
- 不填也不会报错，前端会退回显示整体流水线名称（`team-pipeline`）；但**默认值是 `TODO-检测模型名` / `TODO-分类模型名`，会原样展示给医生，请务必改掉**。

## 四、队友B：分类模块契约

```python
def classify(roi) -> ClassificationOutcome
```

| 项 | 说明 |
|----|------|
| 输入 `roi` | `ROI` 对象（用 `roi.image` 取图；`roi.box`/`roi.score` 可选参考） |
| 注意 | `roi.image` 可能已是裁剪好的病灶图；**若A没裁剪，则是整张原图**，请自行兼容 |
| 返回 | `algorithm.contracts.ClassificationOutcome` |

`ClassificationOutcome` 字段：

| 字段 | 必填 | 取值 |
|------|:--:|------|
| `classification` | ✅ | `肠套叠阳性` / `肠套叠阴性` / `图像质量不佳` |
| `confidence` | ✅ | 0.0 ~ 1.0 |
| `severity` | 可选 | `轻度` / `中度` / `重度`（仅阳性） |
| `treatment_success_rate` | 可选 | 0.0 ~ 1.0（仅阳性） |
| `treatment_advice` | 可选 | 治疗建议文本 |
| `class_probabilities` | 可选 | `{"肠套叠阳性":0.9, ...}` |

> ⚠️ 若阳性时**不填** `treatment_success_rate`，平台会按默认 85% 生成建议文本。能预测就尽量返回。

## 五、A 与 B 之间只约定这一件事

**唯一的约定就是 `ROI`（见 `contracts.py`）**：A 产出 ROI → B 消费 ROI。
除此之外互不干涉：A 怎么定位、B 怎么分类，各写各的。

如果将来想改这个约定（比如 A 想直接传张量而非 ndarray），**先跟平台方说一声**再改。

## 六、如何启用（关键）

两个模块的 `__init__.py` 里各有一个开关：

```python
READY = False     # ← 你的模块实现完成后改成 True
```

**适配层判断逻辑**：
- 两个都 `READY = True` → **自动启用真实流水线**（平台代码一行都不用改）
- 只要有一个 `False` → **自动回退到 Mock**，平台照常能跑

所以你们可以**随时提交半成品**，不会影响平台运行；等两个都好了，真实模型自动生效。

## 八、依赖要求

如果你用到了新库（常见：`numpy` `pillow` `pydicom` `torch` `opencv-python`），
请把它们**加进 `backend/requirements.txt`**，否则平台环境跑不起来。

- 适配层读图（`pipeline.load_image`）本身就需要 `numpy` + `pillow`，所以真实流水线至少要装这两个。
- 回传**标注图**时：给 `bytes` 或文件路径**不需要额外依赖**；给 `numpy.ndarray` 则需要 `pillow`（平台用它编码成 PNG）。

DICOM（`.dcm`）注意：**平台只负责存文件、传路径，DICOM 解析要你自己做**（可用 `pydicom`）。

## 十一、常见问题

**Q：我的模型需要先检测再分类，能一起做吗？**
A：可以。A 做检测、B 做分类，适配层串起来；或者某一边内部自己全做了，另一边做轻量实现也行。只要两个 `detect`/`classify` 契约满足即可。

**Q：我只想做一个模块，另一个暂时空着行吗？**
A：行。`READY` 保持 `False` 即可，平台会走 Mock，不影响你调试自己的部分。
（注意：真实流水线要求**两个都 READY**；只做一个时整条链路仍走 Mock，所以只完成 A 的话，结果页显示的仍是 `Mock`。）

**Q：病灶框怎么展示给医生？**
A：两种方式任选（见第三节）：
- 只返回 `ROI.box` 坐标 → 前端在**原图**上叠加红框并标注「AI 标注」。
- 返回 `ROI.annotated_image`（带框的图，bytes / 文件路径 / ndarray 都行）→ 结果页出现「原图 / AI 标注图」切换，打印报告也优先用标注图。
两者都给时以标注图为准。

**Q：模型名在前端显示成 `team-pipeline` / `TODO-检测模型名` 是怎么回事？**
A：那是没填 `NAME` / `VERSION` 时的回退显示。填上你自己模块里的 `NAME` / `VERSION` 后，结果页会分别显示「检测模型」和「分类模型」两行。
