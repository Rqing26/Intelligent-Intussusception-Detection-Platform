# 融合模型接入说明（team_model）

> 面向：平台维护方、算法队友
> 对象：队友交付的 `team_model.py` + 12 个权重文件
> 状态：**已接入并生效**（平台当前默认走这条模型）

> ⚠️ **先明确职责边界**：这套模型是**预后模型**，不是诊断模型。
> 它输出的是「灌肠复位成功/失败」概率（YOLO 权重里嵌的类别名就是 `fail`/`success`），
> **不具备判断"有无肠套叠"的能力**。平台结果里的 `classification` 目前是**占位值**，
> 等**诊断分类模型**接入后替换。详见第七节第 2 条。

## 二、模型构成

用 `tools/inspect_team_model.py` 勘察出的真实结构（**注意：全是 YOLOv8 分类模型，不是检测模型**）：

| 文件 | 任务 | 类别 | 参数量 | 输入尺寸 |
|------|------|------|------|------|
| `cut_best.pt` | `classify` | `{0: hengqie, 1: zongqie}` | 5,083,298 (yolov8s-cls) | 384 |
| `kfold_heng/fold_0..4_best.pt` | `classify` | `{0: fail, 1: success}` | 5,083,298 (yolov8s-cls) | 416 |
| `kfold_zong/fold_0..4_best.pt` | `classify` | `{0: fail, 1: success}` | 5,083,298 (yolov8s-cls) | 416 |
| `best_model.pth` | ResNet18 | `fc: (2, 512)` → 2 类 | 11,187,158 | 224 |

> 所以这套模型**不做病灶定位**（没有 bbox/分割），只输出分类概率 —— 这也是结果页没有病灶框的原因。

推理流程（见 `team_model._infer`，队友原始逻辑）：

```
读图（含 DICOM 窗宽窗位）
  → 切面模型判定横/纵 → 选对应 5 折 YOLO
  → YOLO 5 折平均 success 概率
  → ResNet18 success 概率
  → 融合：成功率取平均；阴阳取两者"或"；严重度按成功率反向映射
  → 生成治疗建议文本
```

## 三、入口优先级（平台自动判断）

适配层 `algorithm/pipeline.py` 按顺序取第一个可用的入口：

| 优先级 | 入口 | 条件 |
|:--:|------|------|
| 1 | A/B 真实流水线 | `detection.READY` 与 `classification.READY` 都为 True |
| 2 | **`team_model` 融合模型** | 依赖已装 + 12 个权重齐全 ← **当前生效** |
| 3 | Mock 占位 | 以上都不满足 |

判断逻辑在 `pipeline.is_team_model_ready()`，每次请求都会重新检查权重是否到位，
**把权重拷进 `algorithm/weights/` 就自动生效，不需要改任何代码**。

启动日志会明确打印当前用的是哪条路径，例如：

```

```

## 五、平台侧做过的改动

### 5.1 加固（**不改变任何推理结果**）

| 加固 | 说明 |
|------|------|
| 依赖导入保护 | torch/ultralytics 等导入失败不炸平台，自动回退 Mock |
| 线程锁 | 并发首次请求只加载一次模型（原来会重复加载 12 个模型） |
| `torch.load` 兼容 | torch ≥ 2.6 的 `weights_only` 默认值变化有兜底重试 |
| 权重目录可配置 | 环境变量 `ALGO_WEIGHTS_DIR` 覆盖默认路径 |
| 启动预热 | 后台线程预热，医生第一次点检测不用等模型加载 |
| 日志静音 | YOLO 每次推理的 6 行进度默认关闭（`ALGO_YOLO_VERBOSE=1` 可开） |
| 溯源字段 | 结果里补上「分类模型：YOLO5Fold+ResNet18 v1.0.1」与耗时，前端单独展示 |

### 5.2 行为改动：仅一处，且已回退为占位

| 项 | 状态 |
|---|---|
| `classification` 的取值 | **占位值「肠套叠阳性」**（与队友交付版一致，等诊断模型接入） |
| 阴性结果不带「灌肠/手术」建议 | 已加（占位模式下不触发，等诊断模型接入后生效的前瞻性保护） |
| 读图 / 预处理 / 推理 / 严重度映射 / 成功率 / 建议文案 | 全部保持队友原样 |

> 曾有过的错误尝试：一度把 `fusion_pred`（预后成功率>0.5）当作诊断依据来判阳/阴。
> 这属于**用预后退诊断**，语义不成立，已回退；该映射仅保留在
> `ALGO_CLASSIFY_MODE=prognosis` 这个显式开关里作为对照。

环境变量：

| 变量 | 默认 | 作用 |
|------|:--:|------|
| `ALGO_WEIGHTS_DIR` | `backend/algorithm/weights` | 权重目录 |
| `ALGO_PRELOAD` | `1` | 启动时后台预热模型；设 `0` 关闭 |
| `ALGO_YOLO_VERBOSE` | `0` | 是否打印 YOLO 每张推理日志 |
| `ALGO_CLASSIFY_MODE` | `placeholder` | `placeholder`=分类用占位阳性（诊断模型未接入）；`prognosis`=按预后成功率外推（语义不严谨） |

## 七、⚠️ 已知问题（**队友侧待处理**）

### 1. 横切与纵切权重完全相同

`kfold_heng/fold_N_best.pt` 与 `kfold_zong/fold_N_best.pt` 的 **MD5 完全一致**（5 折全对）。
也就是说切面模型判出「横切 / 纵切」之后，走哪条分支**结果完全一样**，切面分类目前没有实际作用。

> 处理方式：队友把真正的纵切权重放进 `kfold_zong/` 即可，平台代码不用改。

### 2. 诊断分类缺失 → `classification` 是**占位值**（不是这个模型判的）

**关键事实**：这套模型只做预后，`classification` 从来没有由它产生过。

| | 说明 |
|---|---|
| 模型实际输出 | 灌肠复位 `fail`/`success` 概率 + 切面 `hengqie`/`zongqie` |
| 模型**不**输出 | 肠套叠「阳性/阴性」—— 它没有这个能力 |
| 结果页的「阳性」来自哪 | 代码里的占位字面量 `classification = "肠套叠阳性"`（队友注释：**"目前按你的要求先预设为阳性"**） |

为什么不能用它外推诊断：「灌肠复位成功」的**前提**是「已经确诊肠套叠」——
拿预后反推有无肠套叠没有临床依据。（队友代码把 `fusion_pred` 注释成「0=阴,1=阳」容易误读。）

**平台的处理**：

```python
classification = decide_classification(fusion_pred)
# ALGO_CLASSIFY_MODE=placeholder（默认）→ 占位值「肠套叠阳性」，等诊断模型接入
# ALGO_CLASSIFY_MODE=prognosis       → 按 success>0.5 外推（语义不严谨，仅作对照）
```

**验证**：`python tools/check_hardcoded_classification.py`
（用纯黑图/随机噪声/医院 Logo 等非医学图像跑，直观显示"任何输入都返回阳性"，
以及 `prognosis` 模式下 Logo 会被判成阴性 —— 说明那个映射本身就是不可靠的。）

> 📌 **待办**：诊断分类模型接入后，把 `decide_classification` 换成它的输出，
> 并在结果里区分展示「诊断模型」与「预后模型」两个来源。

### 2.1 两个字段的语义都还没对上

- `classification`：占位值（见上），需要诊断模型
- `confidence`：`max(yolo_success, resnet_success)` 是**灌肠复位成功率**，
  不是"阳性的概率"，但前端把它当"置信度"展示 —— 同样要等诊断模型接入后修正

平台**没有擅自改动** `confidence`：这套模型只输出成功率，不存在现成的"阳性概率"，
硬编一个公式只会把错误数字包装得更像真的。

### 3. 没有病灶框，也没有标注图

这套模型只做分类回归，**不做病灶定位**，因此：

- `roi_box` 为空 → 影像面板不会叠加病灶框；
- `result_image` 为空 → 结果页没有「AI 标注图」切换，`has_result_image=false`。

将来由检测模块（A）负责输出病灶框或标注图，接入方式见 `docs/算法分工与适配层说明.md` 第三节。

### 4. 5 折集成里有个别折严重偏离（建议队友核查）

实测 5 折对同一张图的输出，部分样本折间分歧极大：

| 影像 | 各折 success | 均值 | 极差 |
|------|------|:--:|:--:|
| `485fd6bb` | `[0.9995, 0.9999, 0.8021, 1.0, 0.0209]` | 0.764 | **0.979** |
| `8a8200c4` | `[0.9999, 0.9828, 0.664, 0.9995, 0.9983]` | 0.929 | 0.336 |
| 其余 17 张 | 折间基本一致 | ≥0.996 | ≤0.02 |

- 19 张里 **2 张（同一张图的两个副本）极差达 0.979**：`fold_4` 只给 0.0209，其余四折都在 1.0 附近。
  简单平均后为 0.764，虽然仍在 0.5 以上（判阳），但**离阈值只差 0.26** —— 再多一折跑偏就会翻转结论。
- 建议队友查一下 `fold_4`/`fold_2` 是否训练不充分或数据划分异常；
  "简单平均"这种聚合方式对单个离群折非常敏感，改成中位数或去掉离群折会更稳。

### 5. YOLO 输出高度饱和（对**预后**结论而言）

19 张真实影像的 YOLO 均值全部 ≥ 0.764，**没有一张低于 0.5** —— 即模型对这批样本
一致预测"灌肠复位会成功"。注意这是**预后**结论，不能当成"这 19 个都确诊肠套叠"的证据。

> 若将来要验证模型能否判出「灌肠复位会失败」，必须补**结局为失败**的病例；
> 现有数据里一例都没有，所以"模型有区分度"这句话目前只在"成功"这一侧被验证过。
