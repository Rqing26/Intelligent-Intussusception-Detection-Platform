## 二、模型构成

| 文件 | 作用 | 输出 |
|------|------|------|
| `cut_best.pt` | 切面分类 | `hengqie` / `zongqie` |
| `kfold_heng/fold_0..4_best.pt` | 横切 5 折集成 | 灌肠复位成功概率（0~1） |
| `kfold_zong/fold_0..4_best.pt` | 纵切 5 折集成 | 灌肠复位成功概率（0~1） |
| `best_model.pth` | ResNet18（fc 改 2 类） | 灌肠复位成功概率（0~1） |

推理流程（见 `team_model._infer`，队友原始逻辑）：

```
读图（含 DICOM 窗宽窗位）
  → 切面模型判定横/纵 → 选对应 5 折 YOLO
  → YOLO 5 折平均 success 概率
  → ResNet18 success 概率
  → 融合：成功率取平均；阴阳取两者"或"；严重度按成功率反向映射
  → 生成治疗建议文本
```

## 三、入口优先级（平台自动判断）

适配层 `algorithm/pipeline.py` 按顺序取第一个可用的入口：

| 优先级 | 入口 | 条件 |
|:--:|------|------|
| 1 | A/B 真实流水线 | `detection.READY` 与 `classification.READY` 都为 True |
| 2 | **`team_model` 融合模型** | 依赖已装 + 12 个权重齐全 ← **当前生效** |
| 3 | Mock 占位 | 以上都不满足 |

判断逻辑在 `pipeline.is_team_model_ready()`，每次请求都会重新检查权重是否到位，
**把权重拷进 `algorithm/weights/` 就自动生效，不需要改任何代码**。

启动日志会明确打印当前用的是哪条路径，例如：

```
检测入口：队友融合模型 team_model（YOLO5Fold+ResNet18）
算法模型预热完成，耗时 682 ms（设备：cpu）
```

## 五、平台侧做过的加固（**未改动任何推理逻辑**）

| 加固 | 说明 |
|------|------|
| 依赖导入保护 | torch/ultralytics 等导入失败不炸平台，自动回退 Mock |
| 线程锁 | 并发首次请求只加载一次模型（原来会重复加载 12 个模型） |
| `torch.load` 兼容 | torch ≥ 2.6 的 `weights_only` 默认值变化有兜底重试 |
| 权重目录可配置 | 环境变量 `ALGO_WEIGHTS_DIR` 覆盖默认路径 |
| 启动预热 | 后台线程预热，医生第一次点检测不用等模型加载 |
| 日志静音 | YOLO 每次推理的 6 行进度默认关闭（`ALGO_YOLO_VERBOSE=1` 可开） |
| 溯源字段 | 结果里补上「分类模型：YOLO5Fold+ResNet18 v1.0.1」与耗时，前端单独展示 |

环境变量：

| 变量 | 默认 | 作用 |
|------|:--:|------|
| `ALGO_WEIGHTS_DIR` | `backend/algorithm/weights` | 权重目录 |
| `ALGO_PRELOAD` | `1` | 启动时后台预热模型；设 `0` 关闭 |
| `ALGO_YOLO_VERBOSE` | `0` | 是否打印 YOLO 每张推理日志 |

## 七、⚠️ 已知问题（**队友侧待处理**）

### 1. 横切与纵切权重完全相同

`kfold_heng/fold_N_best.pt` 与 `kfold_zong/fold_N_best.pt` 的 **MD5 完全一致**（5 折全对）。
也就是说切面模型判出「横切 / 纵切」之后，走哪条分支**结果完全一样**，切面分类目前没有实际作用。

> 处理方式：队友把真正的纵切权重放进 `kfold_zong/` 即可，平台代码不用改。

### 2. 分类结果被硬编码为「肠套叠阳性」

`team_model._infer` 里有队友的 TODO：

```python
classification = "肠套叠阳性"   # TODO: 目前按你的要求先预设为阳性，后续再改
```

所以**现阶段不管输入什么图，结果页都显示「阳性」**，只有置信度、严重度、成功率、治疗建议会随图变化。

> 上线前必须改成由 `fusion_pred`（或融合诊断置信度）决定分类，并补上「图像质量不佳」的判定。

### 3. `confidence` 语义不是"诊断置信度"

当前 `confidence = max(yolo_success, resnet_success)` —— 这是**灌肠复位成功率**，不是"肠套叠阳性"的把握。
在分类被硬编码为阳性的前提下，结果页那句"置信度 100%"实际含义是"灌肠成功率 100%"。
改第 2 条时应一并修正。

### 4. 没有病灶框，也没有标注图

这套模型只做三分类/成功率回归，**不做病灶定位**，因此：

- `roi_box` 为空 → 影像面板不会叠加病灶框；
- `result_image` 为空 → 结果页没有「AI 标注图」切换，`has_result_image=false`。

将来由检测模块（A）负责输出病灶框或标注图，接入方式见 `docs/算法分工与适配层说明.md` 第三节。
